# Decisions
- 2026-11-26: Installed .NET SDK 10.0.404 (winget), Nuke.GlobalTool 10.1.0, Kiota 1.39.0, aws-cdk 2.1149.0. Reason: missing prerequisites.
- 2026-11-26: MediatR pinned to 12.x (MIT) to avoid licence-key friction. Reason: CLAUDE.md §11 fallback.
- 2026-11-26: GitHub Project board needs gh scope 'project' (interactive browser auth). Not possible autonomously; issues F1-F8 created and tracked via labels/milestone + issue list screenshot instead.
- 2026-11-26: CloudFront could not be created (CloudFormation: "Your account must be verified before you can add new CloudFront resources"). The SPA is served from an S3 static-website bucket and calls the ALB directly with CORS enabled on the API; the CloudFront distribution (with /api/* routed to the ALB) stays in the CDK stack behind `-c cloudfront=true`. Reason: account verification needs AWS Support and cannot be done autonomously.
- 2026-11-26: AppConfig profile is a freeform JSON profile (`{"FeatureManagement":{"tariff-estimates":false}}`) read by the AppConfig configuration provider and consumed by Microsoft.FeatureManagement, instead of the typed feature-flag profile. Reason: the typed profile returns a different JSON shape that Microsoft.FeatureManagement does not read without a custom bridge.
- 2026-11-26: Local stand-in for the S3-triggered Lambda is `MeterParser.LocalRunner`, which polls the moto bucket and runs the same `Function.ProcessAsync` code. Reason: moto cannot invoke a .NET Lambda from S3 notifications.
- 2026-11-26: moto returns an x-amz-crc32 header that AWSSDK v4 rejects on SQS JSON responses, so the local SQS client strips it (`LocalHttpClientFactory`, local only). The PriceMock runs as a sidecar container in the API task in AWS.
- 2026-11-26: RDS SQL Server Express is db.t3.small, not db.t3.micro. Reason: on t3.micro (1 GiB) the instance ran out of CPU credits and memory and list queries took 25 s; t3.small is the smallest class that behaved.
- 2026-11-26: AppConfig deletion protection blocks deleting an environment/profile that was polled in the last 60 minutes, which made `cdk destroy` fail. `scripts/destroy.sh` now deletes the AppConfig environment, hosted versions, profile and application first with `--deletion-protection-check BYPASS` (per call, the account-wide setting is untouched).
- 2026-11-26: `scripts/destroy.sh` refuses to delete the bootstrap stack while the app stack still exists. Reason: the first destroy attempt removed the bootstrap roles first and CloudFormation could then no longer finish deleting the app stack; a temporary admin role (created and deleted again) was needed once to recover.
- 2026-11-26: The deployer profile has an explicit deny on `tag:GetResources`, so `verify-destroyed.sh` cannot use the resource tagging API. It relies on direct list/describe calls per service instead (a superset of the checks in SPECS section 11) and says so in its output.
- 2026-11-26: CDK helper Lambdas (bucket notifications, auto-delete objects) create log groups that CloudFormation does not remove; `destroy.sh` deletes any log group containing `GridMeter`.
